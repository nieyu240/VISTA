# VISTA 本地游戏 Benchmark：工作总结

整理日期：2026-11-01（北京时间）。

这个项目将 VISTA 的视觉观察、历史回看和工具调用接到真实游戏环境，
再为实验加入状态与证据记录、过程诊断、成对比较和可视化。
核心价值是让一次分数可以追溯到环境、配置和动作，帮助定位失败原因，
并验证 Agent 改进是否同时带来成功率与成本上的收益。

## 2. 已有实验观察

以下是此前本机保存轨迹的摘要，每种配置主要为单次诊断。
GitHub 代码包保留方法、配置和摘要；原始模型请求、截图与机器环境报告留在本地。
这些数字不是通过本次整理重新测出的成绩。

| 实验 | 已观察到的结果 | 可支持的结论 |
| --- | --- | --- |
| MC 风格采集 `18_01`，seed=42 | 基础提示 17/20 泥土、85%；增强提示 20/20、100% | 同种子单次完成度提高 15 个百分点，尚不能证明稳定提分 |
| 2048 `01_01`，seed=42 | 基础提示 32 动作、89.4 秒；增强提示 21 动作、53.8 秒；均成功 | 本次增强提示动作更少；需要多任务重复验证 |
| 2048 可靠性条件 | 24 动作、48 模型响应、约 157.3 秒，也达到目标 | 状态卡与核验会增加调用和成本，动作减少不能单独当作全面提升 |
| ARC3 `vc33` 思考条件 | 官方分数约 0.303819，通过 1/7 关，仍未通关 | 存在部分进展；预算同时改变，不能只归因于思考模式 |
| MC 零模型审计 | `18_01`、seed=42 的 text-only、repeat、blind 均为 0% | 该局面未被这三种简单控制器绕过，不能推广为全套抗捷径证明 |
| 建筑 perfect fixture | 给定目标和完全匹配状态，完成度 100% | 验证评分器边界；不是 Agent 的实际建造成绩 |

MC 基础提示的 100 次决策中有 49 轮只回复文字；实际执行动作 51 次。
增强提示的 50 次决策实际执行动作 50 次。早期把决策数写成动作数的报告已纠正。
历史上依据模型回复关键字产生的 12/100、48/100 不作为有效基线。

## 3. 评分为什么更可解释

原生结果回答“目标是否达到”；过程报告另外回答用了多少动作、模型调用、
观察和时间，哪些动作被拒绝，以及状态判断引用了哪些实际观测。
Agent 的自我核验不等于独立真值：没有标注或环境检查器支持的语义证据准确率、
隐藏状态准确率、恢复成功率和严格成功率保持缺失，不填零，也不代替原生分数。

同一游戏、任务和种子的结果才能进入配对分析。
任务内先聚合，再按任务和任务内种子做两级 bootstrap；少于两个任务时不计算区间。
不把大量相关步骤当作大量独立样本，不合并不同套件的评分尺度。
当前只支持暂停推理时钟；实时与 token 时钟需要真正支持时间推进的 adapter。

## 4. 与原工作目标的关系

- **MC think/action 分析：**可分开测模型请求端到端耗时和动作工具耗时，并追溯状态读取形式。
  API 不暴露内部推理各阶段耗时，因此不能直接测隐藏思考过程。
- **MC 建筑 Demo：**已有主机侧评分器和固定目标，尚需实际方块状态导出的游戏 adapter。
- **模型速度比较：**已有统一调用接口、预算记录与配对框架；尚未执行 DeepSeek 与其他模型的完整通关比较。
- **饥荒/泰拉瑞亚：**事件格式、日志和评分协议可复用；正式客户端、服务端和状态 adapter 尚未部署。
- **Roguelite：**可复用观察、动作和任务验收；多人规则、关卡复刻和可玩性检验仍需具体实现。

## 5. 验证与后续实验

发布整理时已经通过 21 项离线单元测试、Ruff、Python 编译、PowerShell/Bash 语法检查，
并验证了不携带历史轨迹的仪表盘/API与游戏素材访问。离线测试不会调用模型。
已有轨迹的回放导航和私有请求拒绝访问也在前轮本地验证过。

下一步已准备 18-job MC 矩阵：2 个任务 × 3 个种子 × 3 个条件。
该矩阵尚未执行。先在相同模型、任务、预算和计时模式下完成这些实验，
再决定配置是否值得推广。完整研究设计见[论文启发下的完善方案](论文启发下的Benchmark完善方案.md)。

分享本仓库链接可阅读源码、文档并克隆部署；它不是托管中的在线游戏站点。
本地 `localhost:8765` 地址只能访问各自电脑的服务。
